Methodik — wie aus Notizen Wissenschaft wird

Die sieben Arbeitsweisen des Archivs: von der Recherche über das Quellenmanagement bis zur Publikation als lebendiges Buch — und zur Rolle der LLMs dabei.

01
fundament

Literaturrecherche

Jeder Zweig des Themenbaums beginnt mit einer systematischen Suche: akademische Volltext- und Metadatenindizes, dann Verlagskataloge, dann Handschriften der eigenen Bibliothek. Treffer werden nach Verankerung (Zitationshäufigkeit), Aktualität und Passung zur Leitfrage kuratiert — nicht nach Bekanntheit.

  • Ergebnis der Erstrunde: literatur-fundament v1 — 60 kuratierte Werke, 75 Rohdatensätze
  • Regel: Jede Quelle nennt ihren Beitrag zum Kapitel, nicht nur ihren Titel
  • Primärtexte (Steiner, Nietzsche, Bachtin, Kittler …) werden bewusst separat geführt
02
format

BibTeX-Format

Alle bibliografischen Einträge werden in BibTeX gepflegt — als maschinenlesbare, versionierbare Wahrheit des Archivs. Die Bibliothek des Repos (bibliothek/casmas-alis-2024-2026.bib) ist das lebende Vorbild: Einträge tragen Schlüssel, die in Markdown, LaTeX und Jupyter Books gleichermassen zitierbar sind.

  • Ein Eintrag = ein Objekt mit Schlüssel, Autor:innen, Jahr, Titel, DOI/URL
  • Diffbar in Git — Literaturgeschichte wird Teil der Versionsgeschichte
03
verwaltung

Zotero-Literaturverwaltung

Zotero ist die Werkstatt der Quellen: Sammlungen pro Themengebiet, Tags pro Zweig des Themenbaums, Volltexte lokal. Export nach BibTeX mit einem Klick; das Repo enthält mit zotero_export.py bereits die Brücke. Gruppenbibliotheken ermöglichen kollaboratives Kuratieren.

  • Workflow: Finden → Zotero → Tag (zweig-id) → BibTeX-Export → Commit
  • Anhänge & Notizen bleiben beim Eintrag, nicht in Köpfen
04
publikation

Jupyter Books als modernes Format

Das Archiv publiziert als Jupyter Book: Markdown wird zu HTML, Zitate zu Marginalien, Code zu ausführbaren Belegen. Open Science heisst hier: Der Build ist öffentlich, die Pipeline reproduzierbar (_build_all.py), jede Änderung ein Commit — kollaborative Wissenschaft als gelebte Praxis, nicht als Schlagwort.

  • Struktur: _config.yml + _toc.yml + Kapitel als .md
  • Deploy: GitHub Actions → GitHub Pages → eigene Domain
05
datenmanagement

Datenmanagement für Autor:innen & Editor:innen

Ein interaktives Buch lebt in mehreren Gestalten gleichzeitig: Jupyter/HTML fürs Web, E-Book (EPUB via Calibre) für Reader, PDF via LaTeX für Druck und Archivierung. Datenmanagement heisst: eine Quelle, viele Ausgaben — Markdown als Single Source of Truth, Formate als Build-Artefakte.

  • Markdown → HTML (Jupyter Book) · → EPUB (Calibre/Pandoc) · → PDF (LaTeX/Tectonic)
  • Altversionen werden archiviert (altversionen/), nie gelöscht
  • Assets (Bilder, Audio) versioniert, mit festen Pfaden
06
schreiben mit ki

LLMs für wissenschaftliches Schreiben

LLMs sind hier Werkzeug, nicht Autor: Sie strukturieren Rohtexte, schlagen Gliederungen vor, finden Literatur, redigieren Stilbrüche — unter vier Regeln: (1) jede generierte Aussage wird verifiziert, (2) keine erfundenen Referenzen, (3) die Stimme des Werks (Footprint) hat Vorrang vor Glättung, (4) der Mensch entscheidet, was stehen bleibt.

  • Stärken: Clustering, Exposé-Rohlinge, Zusammenfassen, Gegenlesen
  • Grenzen: Fakten, Zitate, Urheberschaft — alles prüf- und zuordenbar halten
07
archiv & bibliothek

LLMs im Archiv- und Bibliothekswesen

Das Archiv nutzt LLMs dort, wo Bibliothekswissenschaft längst Maschinen einsetzt: Erschliessung (Themen-Clustering der 315 Notizen), Metadaten-Anreicherung, Retrodigitalisierung, Normdaten-Mapping — aber mit archivarischer Sorgfalt: Provenienz bleibt dokumentiert (welcher Text stammt woher, welcher Schritt war maschinell), und der Abgleich-Bericht (fb_export/ABGLEICH-BERICHT.md) ist Teil der Provenienzkette.

  • Erschliessung: Clustering & Verschlagwortung als Vorschlag, Kuratierung als Menschenwerk
  • Provenienzprinzip: maschinelle Schritte sind markiert und reproduzierbar
  • Fernziel: Linked-Open-Data-Anbindung der Bibliothek
